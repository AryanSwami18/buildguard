You compare an extracted build Wiki instruction with an extracted Bash build script.

Use only the two supplied BuildInstruction objects. Do not use external knowledge,
rewrite either instruction, or infer that two steps match just because their
descriptions sound generally similar.

Compare every step in both inputs. Match steps only when they describe the same
build operation, accounting for action, packages, commands, paths, URLs,
repository, ref, commit, version, Docker image, Dockerfile, build arguments,
environment, patches, build tool, dependencies, and source context. Equivalent
shell syntax or different wording can represent the same operation. Preserve
differences in concrete values as conflicts; do not silently treat them as equal.

For each Wiki step, return exactly one entry. A Wiki instruction may require
several Bash commands; include every Bash step needed to carry out that Wiki
instruction in `bash_step_ids`. Set `bash_step_id` to the first/primary ID for
compatibility, and include that same ID in `bash_step_ids`.
- matched: the Bash script implements the same operation and its concrete values
  agree where both sources provide them.
- conflict: the same operation is present but there is a meaningful action or
  value disagreement.
- missing: no Bash step implements the Wiki operation.
- out_of_scope: the Wiki step only downloads or launches the same build script
  whose internal commands are being compared. The script does not implement its
  own bootstrap step; explain why it is outside this comparison.

For every missing, conflict, or extra entry, also provide:
- `category`: one of `missing_step`, `undocumented_step`,
  `parameter_value_mismatch`, `version_inconsistency`,
  `dependency_inconsistency`, `command_mismatch`,
  `configuration_mismatch`, or `other_deviation`.
- `recommendation`: one concise, actionable correction or review action grounded
  in the supplied source values. Do not invent replacement versions or commands.
  For an undocumented Bash step, recommend confirming whether it is required;
  document it if required, or remove/disable it only if it is unnecessary.

For matched and out_of_scope entries, use null for `category` and
`recommendation`.

- `field`: the BuildStep field being compared (for example `version`, `commit`,

- `bash_step_id`: the selected Bash step that contains the conflicting value.

Use resolved values only when the supplied environment/default data proves the
resolution. Do not compare values merely because they occur somewhere in the

Accuracy rules:

- Mark a Bash step extra only when it is an undocumented build operation or
